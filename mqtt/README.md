# MQTT API documentation generation

The MQTT reference is observed from real production MQTT calls made by the
existing unit tests. It is intentionally not generated by parsing C++ source
and does not use a separate device emulator.

The test-only flow is:

```text
existing test
  -> production Mqtt publish/subscribe logic
  -> MqttInterface publishImp/subscribeImp adapter
  -> optional documentation recorder
  -> existing GMock publishTest/subscribeTest assertion
```

`MqttDocumentationScenario` is an explicit RAII scope. Only operations inside
such a scope are recorded. This prevents retained cleanup, invalid-input,
no-op, and Home Assistant traffic from silently becoming part of the public
API. A scenario carries its stable ID, channel type and function, category,
channel number, description, and the exact device prefix used for
normalization. Nested scenarios are rejected. Retained publications with an
empty payload are classified as `cleanup` at operation level, including when a
production call mixes cleanup and public state traffic. Operation categories
take precedence over the scenario category; a `mixed` scenario defaults its
non-cleanup operations to `public`.

The recorder is disabled unless `MQTT_DOC_CAPTURE` is set. It sorts scenarios
and operations before JSON serialization and normalizes only the known device
prefix, the scenario channel number, and the structural electricity-meter
phase component. Normal test runs do not write documentation files.

Run the complete generation pipeline from the repository root:

```bash
extras/tools/mqtt-docgen/generate.sh
```

The script runs all `Mqtt*` tests with normal assertions enabled, writes
`observed.json`, combines it with `metadata.json`, renders the English and
Polish public and Home Assistant Markdown files, and runs renderer validation
tests. Polish text is maintained as a translation overlay in
`translations.pl.json`. An existing test binary can be selected with
`MQTT_TEST_BINARY`; otherwise the standard `extras/test/build` location is used
and built when absent.

The renderer reports missing and stale metadata as warnings. Conflicting QoS,
retain, direction, or payload types are errors. Home Assistant scenarios are
rendered separately, while `internal` and `cleanup` operations remain observable
in JSON but are excluded from the main public guide.

The generated documentation is necessarily coverage-driven. A topic is
documented only when a deliberately marked test scenario exercises it. See
`coverage.md` for the current inventory and deferred variants.
