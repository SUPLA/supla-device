Detailed Description

One firmware update attempt.

SuplaDevice owns the updater, calls start() and then calls iterate() until the attempt ends. The updater implements version discovery, download, verification and installation for its platform.

To use your own updater, derive from SwUpdate and register a factory before SuplaDevice.begin(). This example assumes GitHubSwUpdate is defined by the application and its constructor forwards the arguments to SwUpdate.

// In setup(), after configuring the device and before begin().
SuplaDevice.setSwUpdateFactory(
[](SuplaDeviceClass *device,
const char *url,
Supla::SwUpdateMode mode) -> Supla::Device::SwUpdate * {
return new GitHubSwUpdate(device, url, mode);
});
SuplaDevice.setAutomaticFirmwareUpdateSupported(true);

The factory receives the configured update server URL or the SUPLA default. SwUpdate copies it into its own buffer. The factory may supply a different URL to the constructor, such as the project's GitHub Releases endpoint. The factory's URL argument is valid only during the call. Return a new object for each attempt, or nullptr to decline that attempt. Register a nullptr factory to restore the platform default.

Read mode and policy flags in iterate(). SuplaDevice attaches the observer and applies beta, securityOnly and skipCert after construction. OnlyCheck checks for a new version without writing to flash. CheckAndUpdate and PeriodicCheckAndUpdate may install an update. A retry creates another object in CheckAndUpdate mode.

Only CheckAndUpdate switches the device to SW update mode, which sets the status and disconnects protocols before start(). In PeriodicCheckAndUpdate the device stays connected and keeps running its normal loop, so an updater that installs in this mode must not block and must cope with the network being shared with the SUPLA connection.

SuplaDevice sets the security-only flag for periodic OTA under the SecurityOnly policy and for a security update requested from Cloud. Call isSecurityOnly() when selecting a release. The updater determines which releases qualify using its update source, for example a security flag in the project's release manifest. If no newer security release is available, use the up-to-date path below. On retry, the security-only flag is carried over from the previous attempt.

When OnlyCheck finds an update, set newVersion before ending the attempt so SuplaDevice can report it to Cloud. For example, given a discovered version string called version (include <string.h> for strlen and memcpy)

delete[] newVersion;
const size_t length = strlen(version) + 1;
newVersion = new char[length];
memcpy(newVersion, version, length);
abort = true;
notifyFinished(true);

If the installed firmware is already up to date, leave newVersion unset.

abort = true;
notifyFinished(Supla::Device::SwUpdateResult::UP_TO_DATE);

To install an update, use the platform OTA API to write the image, verify it and select it for the next boot. Only then report installation success.

finished = true;
notifyFinished(Supla::Device::SwUpdateResult::UPDATED);

For a failed attempt, set abort and report FAILED (or notifyFinished(false)). Set retryAllowed for a transient failure when installing. SuplaDevice checks abort first, releases the updater on either terminal state and schedules a restart on finished. An OnlyCheck attempt is never retried, so a failed check cannot turn into an installation.

A reported failure takes precedence over newVersion in the Cloud result. Otherwise, newVersion means an update is available, and retryAllowed without a version means an error. With neither flag nor a new version, ending the attempt with abort reports that no update is available.

The updater may be deleted from SuplaDevice's destructor, which for the global SuplaDevice runs during static destruction at program exit. Keep the destructor simple: do not rely on other global objects or join threads that depend on them.
